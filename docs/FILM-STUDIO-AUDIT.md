# WINDELS AI FILM STUDIO — repository audit & implementation report

**Date:** 2026-10-31
**Scope:** the existing Faceless Studio / WINDELS AI OS repository, its AI Filmmaking
subsystem, and the 12 modules requested in the upgrade brief.

This report follows the brief's rule: *a feature counts only when it works end to
end.* Each entry below is backed by code paths, database columns, API routes and
automated tests, or it is explicitly listed as missing.

---

## 1. How this audit was produced

1. Read the full film subsystem: `server/film/*` (screenplay, scenes, series,
   providers, assembly, credits), `server/routes/films.js`, the film React
   pages, the schema in `server/db.js` and the existing film test suites.
2. Ran the untouched test suite as a baseline (174 tests, all passing).
3. Implemented the work in phases (§4 Phase 1, §5 the production agent,
   §6 the remaining modules) and re-ran the whole suite after each phase.
4. Verified the desktop bundle builds before every commit.

Nothing below is inferred from a button label or a table name alone.

## 4. Phase 1 — implemented and tested in this change

### 4.1 Cinematography controls (Modules 1 + 3)

- New `server/film/cinematography.js`: closed vocabularies plus prompt phrases
  and depth-of-field descriptions per lens.
- `film_scenes` gains `shot_size`, `camera_angle`, `lens`, `lighting`,
  `color_grade`, `composition` (additive migration; legacy rows default to `''`).
- `PATCH /api/films/:id/scenes/:sceneId` validates the values — an unknown shot
  is a `400`, not a silently ignored field.
- `scenePrompt()` now emits a cinematography sentence that reaches the real
  provider request, e.g.:
  `Cinematography: close-up, low angle looking up at the subject, 85mm lens,
  shallow depth of field with creamy background bokeh, dolly pushing in, rim
  lighting, teal and orange blockbuster grade, composition: subject on the left third.`
- The AI screenplay prompt asks for the same fields, and the offline template
  draft now includes real directorial choices so an offline storyboard is usable.
- UI: each scene card exposes shot size, angle, lens, movement, lighting, grade
  and a composition note.

### 4.2 Locations library (workflow step 4 + continuity engine)

- New `film_locations` table (film-, series- or user-scoped) with name,
  description, time of day, weather, palette, style and a reference-image slot.
- `server/film/locations.js`: CRUD with ownership checks and scope rules.
- Routes: `GET/POST /api/films/:id/locations`, `PATCH/DELETE
  /api/films/:id/locations/:locationId`.
- `film_scenes.location_id` links a scene to a saved location. Linking sets the
  scene's on-screen location name; deleting a location **detaches** its scenes
  instead of leaving a dangling reference.
- `scenePrompt()` prefers the saved set description, time of day, weather and
  palette over free text, which is what keeps later episodes in the same room.
- UI: a dedicated **Locations** step with the library, per-scene usage counts and
  a link selector on every scene.

### 4.3 Continuity / quality control engine (workflow step 9)

- New `server/film/continuity.js` and `GET /api/films/:id/qc`.
- Eight real checks computed from persisted state: scenes present, real clips on
  disk, failed generations, shot-direction coverage, cast reference images,
  cast membership of every speaking name, location linkage, runtime vs target,
  dialogue TTS availability and final render presence.
- Each check returns `pass | warn | fail | skip` with evidence and a score. A
  missing provider produces `clips: fail` — QC never passes by default.
- UI: a Quality Control card on the Assemble step.

### 4.4 Formats (workflow step 1, Module 8)

`advertisement`, `music_video` and `cinematic_scene` are now first-class project
types with their own defaults, in the API enum, the screenplay planner, the hub
cards and the new-project form. Existing formats are unchanged.

### 4.5 Compatibility

- All schema changes are additive (`initializeDatabase` migration is idempotent).
- No existing route, table or response shape was removed.
- No new environment variables or providers are required for anything above.

## 5. Phase 2 — AI Production Agent (implemented and tested)

The agent is an **orchestrator, not a second implementation**. Every stage calls
the services that already existed (`generateScreenplay`, `saveScreenplay`,
locations CRUD, `directScenes`, `requestAllScenes`, `filmQualityReport`,
`requestAssembly`). No prompt, provider, credit rule or FFmpeg command is
duplicated — the audit's "no parallel infrastructure" rule holds.

### 5.1 API

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/films/production/start` | Parse a free-text brief, create the project, run the free stages |
| `GET` | `/api/films/production` | List the caller's productions and the stage definitions |
| `GET` | `/api/films/:id/production` | Live stage board: statuses, scene counts, QC, credits, failures |
| `POST` | `/api/films/:id/production/advance` | `{action: "generate" \| "assemble" \| "retry" \| "sync"}` |
| `POST` | `/api/films/:id/production/cancel` | Stop the run and cancel in-flight scene jobs |

Persisted in `film_productions` (one row per project, JSON stage board), added to
the existing additive migration loop.

### 5.2 Stages and gates

```
analyze → screenplay → cast → locations → direct   (automatic, no spend)
   → generate   [approval · credits]   → qc
   → assemble   [approval · credits]   → export
```

- The brief parser derives format, runtime, genre, language and cast size
  deterministically (no AI call), so the run is reproducible offline.
- The screenplay stage uses the existing generator and reports honestly whether
  the result was AI or a labelled local draft.
- The locations stage materialises every unique on-screen setting as a real
  `film_locations` row and links each scene to it.
- The direction stage fills any scene without shot direction from a deterministic
  palette, so the QC "directed scenes" check cannot be gamed.
- Generation and assembly refuse to run unless the caller explicitly names the
  action; both surface the underlying credit preflight (402) or provider (503)
  error unchanged.

### 5.3 Completion rule

A production is marked `completed` **only** when `final_video_path` points at a
file that exists and the export stage derives `done` from it. With no provider,
approving generation returns `503 video_provider_unavailable`, the run becomes
`blocked`, the failed scene numbers are listed, and export never appears.

### 5.4 UI

`/app/films/agent` (new entry in `FILM_PAGES`, so it appears in the studio nav,
sitemap and mobile menu): a brief form, a live stage board, approve/retry/cancel
actions, a QC summary and the agent's honesty rules. It polls the snapshot every
4 s, so progress made by the background worker appears without a refresh.

## 6. Phases 3 and 4 — editing, voice, canvas and the model registry

### 6.1 Voice takes (Module 6)

`GET/POST /api/films/:id/voice` records real per-scene dialogue WAVs with the
configured TTS engine (meSpeak locally, OpenAI or ElevenLabs with a key), stores
duration from the actual file and streams the take at
`GET /api/films/:id/scenes/:sceneId/voice`. Re-recording is explicit (`force`).
A scene with no dialogue is reported as silent rather than given a fake take.
Lip-sync stays out of the UI because no lip-sync provider exists; the panel says
so instead of showing a dead button.

### 6.2 Storyboard, poster and character art (Module 4)

`server/film/storyboard.js` reuses the provider abstraction in
`server/media/images.js` (extended with `generatePromptImage` and
`imageProviderStatus`). Frames are rendered from the **same** `scenePrompt` the
video provider receives, so the still and the clip share cast, location, shot
size, lens, lighting, grade and palette. Files live in
`storage/film_<id>/storyboard`, are served by `GET .../storyboard/:frameId/image`,
and are de-duplicated by `(film_id, scene_id, kind)`.

Procedural art is deliberately not used as a character face reference: only a
real AI provider's portrait sets `reference_image_path`.

### 6.3 Timeline edits that change the render (Module 10)

New scene fields `transition` (`cut`, `fade_black`, `dip_white`), `trim_start`
and `trim_end` are validated by the API, persisted, surfaced in the step 8
timeline, and applied inside `normaliseClip` while each clip is re-encoded onto
the master canvas. Because the concat stays stream-copy, fades and trims do not
add a render pass. `tests/filmmaking.test.js` renders a film with a fade and a
trim and asserts the MP4 is still produced.

### 6.4 Creative Canvas (Module 9)

`/app/films/canvas` saves flows in `film_flows` and executes them in topological
order (`server/film/canvas.js`). Node types call existing services only:
`text`, `screenplay` (`generateScreenplay` + `saveScreenplay`), `image`
(`generatePromptImage`), `voice` (`synthesizeScene`) and `scene`
(`requestSceneGeneration`, so credits and provider checks are identical to the
normal pipeline). Cycles and dangling edges are rejected (400). A failing node
stops the run, skips everything downstream and records the real error.

### 6.5 Model registry (Module 12)

`/app/films/models` renders `GET /api/films/models`: live readiness per provider,
model ids, durations, aspect ratios, cancellation and reference-image support,
and the credit price per six-second scene from the same engine that charges
renders. There is no fake switch: enabling a provider is an operator action and
the page says exactly which environment variable each one needs. Tests assert no
key material is present in the payload.

### 6.6 Deliberately not shipped

Motion transfer, rotoscoping, video-to-video, lip-sync and dubbing require
providers that are not configured. They are documented and shown as absent, not
wired to buttons that cannot work.

## 6.9 Phase 5 — closing every partial module

This phase kept the rule that a module counts only when it works end to end, and
re-verified each one against the real backend.

### 6.9.1 Props continuity (workflow step 4)

`server/film/props.js` + `server/film/propPrompt.js`: `film_props` (shared or
project-scoped) and `film_scene_props` (per-scene state). Props are injected into
every prompt through `scenePropsForPrompt()` and are surfaced in
`GET /api/films/:id` as `props` (library) and `sceneProps` (map by scene).
Prompt helpers live in a DB-only module so `scenes.js` can use them without a
circular import.

### 6.9.2 Character depth and cast library (Module 2)

`film_characters` gains `wardrobe`, `expressions`, `relationships`, `age_range`
and `is_library` (additive migration). `POST /api/films/characters/:id/clone`
copies a library character into a project, refusing a duplicate with 409
`character_exists`; `GET /api/films/cast-library` lists the reusable cast.

### 6.9.3 Advertisement studio (Module 8)

`server/film/ads.js` persists brand kits, attaches one to a project (brand clause
also reaches image/video prompts), writes 3–5 distinct creative angles with the
same screenplay engine and stores them as `ad_variants`. Applying a variant
rewrites the project's scenes. Variants carry an explicit `aiGenerated` flag.

### 6.9.4 Queue-backed storyboard and voice

`POST /api/films/:id/storyboard|voice` accept `{queue: true}` and answer 202 with
a job id; `film_storyboard_batch` and `film_voice_batch` are processed by the
worker in bounded rounds, so a 60-scene film no longer needs one long request.

### 6.9.5 Multi-track editing (Module 10)

`server/film/editing.js` adds `speed_factor`, `vfx_preset` and `overlay_json` to
scenes (`POST /:id/scenes/:sceneId/track`, `GET /:id/editing`). FFmpeg applies
the speed ramp (`setpts`), one of eight local looks, and a timed `drawtext`
overlay while the clip is normalised. Values are escaped for the filtergraph;
a quote inside overlay text used to break the chain, which the render test now
guards against. Every preset is proven by rendering a real MP4 in the suite.

### 6.9.6 Motion transfer, VFX and lip-sync (Modules 7 + 6)

`server/film/vfx.js` separates local looks (always available) from motion
transfer, and `server/film/lipsync.js` handles lip-sync. Both queue worker jobs
(`film_motion`, `film_lipsync`) that run against Replicate or fal using the same
credentials as the video providers. They require inputs the studio already owns
(a storyboard still for motion, a clip **and** a voice take for lip-sync) and an
explicit model id — no model name is invented. Without a key they answer 503
`motion_transfer_unavailable` / `lip_sync_unavailable`, the UI disables the
buttons and labels them "needs key", and nothing is changed.

### 6.9.7 Admin film controls (Module 12)

`server/routes/film-admin.js` (mounted at `/api/admin/film` before the general
admin router) exposes `GET /ops` (provider readiness + disabled list, queue
counts per job type, last ten failed jobs, production/scene snapshot, rendered
film count), `POST /providers/:providerId {enabled}` and
`POST /jobs/retry-failed`. Toggling a provider is enforced, not cosmetic:
`resolveEnabledVideoProvider()` consults `provider_settings` before routing.
The admin UI gains a **Film studio** tab with the same data and controls.

### 6.9.8 Frontend

- `src/pages/film/AdStudio.jsx` + `FILM_PAGES` entry `/app/films/ads` and route.
- Timeline scene rows gain a collapsible **Track** editor (speed, look, overlay
  text and timing, split point) plus gated lip-sync/motion buttons.
- Cast step gains wardrobe, age range, expressions, relationships, library
  opt-in, concept art and a cast-library picker.
- Locations step gains the props sheet; Storyboard and Voice steps gain
  "render/record all in background" buttons.

All of it uses the existing cards, buttons, grid and nav — no homepage restyle.

## 6.10 Delivery pass — overlays, stems, logo, revision and scheduling

The last set of gaps was closed with features that can be verified entirely on
this machine (no provider key needed), because they are FFmpeg or database work:

- **Picture-in-picture overlays.** Owners upload images with
  `POST /api/films/:id/upload` (`kind=overlay`); they are registered in
  `metadata.overlayAssets` and listed by `GET /api/films/:id/overlays`. A scene
  track can reference an overlay by **id** (never a path), with corner position,
  scale, opacity and a time window. `assembly.js` builds a real
  `filter_complex` (`scale → format=rgba → colorchannelmixer → overlay`), so the
  image is in the MP4 — the test samples the rendered pixel and asserts the warm
  overlay colour against the navy scene. Deleting an asset clears every scene
  reference first, so a render can never point at a missing file.
- **Brand logo compositing.** `POST /api/films/brand-kits/:id/logo` stores a logo
  privately; assembly burns it into the bottom-right of the finished cut for any
  project with that kit attached (`brandLogo: true` in the render result). A logo
  failure is logged and the clean cut is kept rather than failing the render.
- **Audio stems.** Assembly now builds dialogue, SFX and music as three separate
  tracks and publishes `stems/voice.wav`, `stems/sfx.wav` and
  `stems/music.<ext>` next to the final cut. `GET /api/films/:id/stems` lists
  them and `GET /api/films/:id/stems/:kind` downloads one (verified RIFF/WAV).
- **Natural-language revision.** `POST /api/films/:id/production/revise`
  rewrites the screenplay from a director's note, then rebuilds cast, locations
  and direction, and returns the recomputed stage board. It refuses with 409
  `production_locked` once paid clips exist instead of orphaning them.
- **Scheduled unattended runs.** `POST /api/films/:id/production/schedule`
  queues `film_production_run` at a future time (dedupe key per project, so
  re-scheduling moves the same job). The snapshot reports `scheduled` and
  `scheduledFor`; the worker performs the same approval-gated generation.
- **Product shots.** `POST /api/films/brand-kits/:id/product-shot` generates a
  square product image from the kit's own copy with the configured image
  provider and stores it next to the logo (`GET .../product-image`). Offline it
  is the procedural renderer, reported as `aiGenerated: false`.
- **Provider health.** `GET /api/admin/film/health` contacts only providers that
  have credentials (Replicate account endpoint, fal root, Veo model list) with a
  4s timeout and reports status/latency, or `checked: false` with the reason. The
  admin Film studio tab has a **Check health** button.

The lip-sync and motion-transfer transports are additionally verified against a
local wire-protocol double (`tests/film-gated-providers.test.js`): the double
receives the data-URI payloads, the code polls, downloads the MP4, probes it and
replaces the scene clip. Live vendor calls remain unverified — that needs a real
key, not code.

UI: the timeline track editor gains an overlay-image picker and upload; Ad Studio
gains logo upload per brand kit; the production agent gains a revision note and a
schedule control.

5. a production is only complete when a rendered file exists, and `sync`
   persists `completed` with a timestamp;
6. failed scenes are reported with their scene numbers, `canRetry` is true, and a
   retry stays blocked rather than pretending to succeed;
7. cancelling stops the run and further paid work returns `409
   production_cancelled`;
8. productions are private (403 for another user) and listed for their owner.
